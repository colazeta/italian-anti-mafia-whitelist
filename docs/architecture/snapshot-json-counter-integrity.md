# Snapshot JSON counter integrity

The approved-source backfill exposed three false integrity failures after successfully storing Prato listed and Grosseto listed/applicant snapshots. Their diagnostics contain Python integer-keyed `section_counts` maps. Sorting keys before JSON serialisation orders 1,2,...,10 numerically; after JSONB storage the same object has string keys, which sort 1,10,2,... . The persisted source values were unchanged, but rehashing with the original serializer produced a different byte order.

New canonical snapshot bytes normalise the payload through JSON before sorting keys. Persistence uses that same normalised payload for comparison and storage, so repeated writes compare the actual JSON data model rather than Python integer keys against JSON strings. Caller-owned records/diagnostics are untouched. Existing payloads with string keys retain their exact hash. No source capture, snapshot, processing provenance or public release is rewritten.

For the three affected parser names only, the verified reader can reconstruct the documented old `section_counts` encoding (keys strictly1..10, nonnegative integer counts) and requires its FULL original stored SHA-256 to match exactly. This is a separate retained encoding check, not a count-only acceptance or a digest replacement. Every source field and all diagnostics remain covered; changed records/counts fail. Other unknown legacy encodings remain quarantined. The backfill can reuse such positively verified retained snapshots rather than erase or duplicate them.

Tests cover JSON and actual PostgreSQL JSONB round trips, unchanged caller data, exact legacy hash validation and tampered record/count rejection. The existing PostgreSQL persistence/idempotence/concurrency check now includes integer section counters in its synthetic input and verifies the digest of the actual read-back JSON. Production acceptance requires the next protected batch to read and verify the retained Prato/Grosseto snapshots without their previous integrity quarantines. Semantic attribution, canonicalisation and public approval remain separate.
