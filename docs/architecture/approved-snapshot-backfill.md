# Approved-source private snapshot backfill

The changed-capture worker deliberately ignores bytes equal to the reviewed publication manifest. This leaves a gap when a source edition was reviewed and published before its private parse snapshot was materialised. `approved_snapshot_backfill` fills only that absence, using the existing protected evidence-archive workflow, store, writer and serial concurrency group.

Selection requires a complete labelled set of exact approved SHA-256 inputs and a correctly associated immutable source capture. Select the latest matching capture, even when a later changed document also exists. Discovery captures are never relabelled. The common parse configuration retains the reviewed reference date only when every input label/hash exactly matches the reviewed source; changed inputs retain an unknown date. Original capture times and declared dates are not rewritten, and no SourceEdition is created.

Before parsing, query existing succeeded snapshots by parser name, complete reviewed configuration hash and full labelled content hashes across prior code revisions. Independently rehash matching snapshot records and diagnostics and reject conflicting interpretations or QA drift. This is a missing-snapshot backfill, not a forced parser upgrade. Missing inputs are processed newest reviewed date first, with four materialisation attempts per shard (hard CLI ceiling eight). Deferred sources remain explicit. Existing source-only transactions, archive hash verification, capture persistence and independent snapshot readbacks remain mandatory. Lodi/Milano edition-review gates remain unchanged.

Reports stay in the private immutable store with exact readback; the console exposes aggregate counts only. Zero public promotions and zero canonical attribution are asserted. Source-quality flags fail acceptance. Trusted main-branch robot push completions may trigger the same worker, alongside existing scheduled/manual triggers; PR code and artifacts are excluded. Post-merge acceptance must inspect the protected run and query actual persisted snapshots, rather than treating CI or a selector commit as database evidence.
