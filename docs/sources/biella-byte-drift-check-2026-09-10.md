# Biella mutable HTML approval check — 10 September 2026

The official Biella White List resource is the Prefecture HTML page itself rather than a versioned attachment. The public build had pinned raw SHA-256 `636389e9980b58b80e3ef5338feca39221db934b6b7ccb0f29b8d286c95dca53`. On 10 September 2026 the same official URL returned different raw byte representations while the parsed tables remained stable.

This drift was not treated as permission to refresh a raw hash blindly. A dedicated audit parsed repeated current downloads with the already approved Biella parsers and compared all parsed source-semantic fields against the published Biella observations, excluding only raw capture SHA-256 and runtime parser name/version. The downloads produced exactly 130 listed-source observations and 109 applicant-source observations. Their approved semantic digests are `8c2cf30eed0ed39673be5a52af1e11763f28ebd000607e1c0e995935b55cf1bd` for the listed source and `4419690a935c921f52b5ffbbf03fefa0253a04d79289baa7b7dce179f0cd8f6d` for the applicant source.

For this explicitly identified mutable structured source, raw-byte identity is not a stable edition boundary. The builder therefore uses a source-specific `semantic_sha256` approval mode. It still hashes and retains the exact downloaded bytes as observation provenance, still applies the approved parser and row-count invariants, and additionally fails closed unless the parsed semantic digest matches the approved value exactly. The approval-mode fields remain internal configuration and are not added to the public source-report contract. All other sources continue to use strict raw-SHA approval unless explicitly configured otherwise.
