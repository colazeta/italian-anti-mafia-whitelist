# Source-only historical capture/check reconciliation

The protected ordinary transformer now includes a bounded, idempotent reconciliation of previously acquired Lodi listed, Lodi applicants and Milano combined historical originals, pinned to the four reviewed SHA identities already used in the historical source audit. It reuses the existing workflow, evidence provider, database writer, connection and concurrency group; there is no new crawler, timer, job, privilege or infrastructure. The September Milano boundary with no verified complete acquisition remains **unknown**, not fabricated from a digest.

The reconciler scans at most 64 CaptureCatalogue items in each of the three existing source-specific private prefixes. It requires a complete listing for the series, the exact already reviewed byte hash, canonical immutable capture/check UUID, full manifest, verified catalogue receipt, independently verified original size/hash and explicit persisted provenance classifications for origin, authority rank and resource type. It neither mutates nor invents these classifications. It never acquires live URLs and cannot use a capture timestamp, file label or SHA as an administrative edition date.

Each eligible check is passed unmodified to the pre-existing `persist_archived_capture` writer, which verifies archive integrity and refuses existing UUID/content metadata conflicts. The writer requires existing registered SourceSeries and inserts source provenance only: source_resource, content_object, source_capture, where missing. The caller commits and independently reads the exact capture/check, digest, byte size, durability, series, captured timestamp, official resource identity and classifications using a new TLS database connection. A successful INSERT without matching post-commit readback is counted as a failure, not as verified recovery. Retrying an existing identical capture is a readback reuse, not another acquisition. No source edition, interpretation, semantic projection, canonical fact or public record is created.

Only bounded aggregate counts leave the protected environment: candidate pins/checks, newly registered originals/checks, independently verified relational capture checks, incomplete listings, metadata blocks and failures. No private source URL, capture UUID, row value, storage key or database credential is printed. Missing provider/SQL access fails closed for this lane but does not prevent independent ordinary transformations. A completed workflow with historical reconciliation counters of zero is not evidence of materialisation. No control here attests independent R2 backup, restore or public approval.

Production acceptance requires: exact-head tests and post-merge CI, positive protected worker counts, independent Neon SQL inspection of the three historically pinned ContentObjects and associated capture/check rows, repeat-run idempotence, and unchanged zero edition/semantic/canonical/publication boundaries. Until these pass, status is implemented/tested rather than production-verified. Recovery acceptance #16 remains independent of this source-only reconciliation.
