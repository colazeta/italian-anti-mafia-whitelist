# Private Cosenza source QA

`python -m white_list_archive.normalisation.cosenza_qa --capture-id UUID --parse-run-id UUID --code-revision EXACT_GIT_SHA --expected-count N` produces aggregate JSON contract `cosenza-source-qa-v1` in a read-only transaction. Run it after capture-only persistence and keep its output in private operational evidence. No names, identifiers, source rows or reviewer details are emitted. A failed structural check raises and must fail the invoking job; a successful command does not mean semantic or publication readiness. Workflow callers must inspect individual gates, not only exit status.

Every report names its input capture, rich run, source/snapshot SHA-256, original source-parser code revision, separate QA code revision (`--qa-code-revision`, default `GITHUB_SHA`), observation timestamp and record denominator. Full snapshot rehash plus complete parsed-row/field/mention readback validates structural/parser lineage. Calendar validation is separate from administrative date interpretation. Identifier shapes/scheme ambiguity, cross-name identifiers, unparsed populated fields and source outcome distributions are review candidates; they neither establish identity nor legal effect. Counts of identifier/date tokens have different denominators from records. `source_fact_review` remains unknown where candidates need review. Unknown status text stays unknown; disappearance, nominal expiry and renewal text never create revocation events.

Edition attribution and publication are independent gates. Existing projector code requires a unique linked edition and reference date but does not independently authenticate approval or materially assess identity/attribution statuses. A caller must add a reviewed attribution control before semantic execution. The optional `--review-decision` JSON is a proposed evidence envelope, not an approval mechanism or a change to approval rules:

- exact keys: `contract`, `capture_id`, `parse_run_id`, `snapshot_sha256`, `edition_id`, `reviewer`, `reviewed_at`, `evidence_reference`, `decision`, `identity_basis`, `reference_date_basis`, `population_scope_basis`, `sector_scope_basis`;
- contract `edition-attribution-review-v1`, decision `accepted`, exact input pins and a unique existing same-series edition link;
- nonempty reviewer/evidence reference and each identity/date/population/sector basis and a timezone-aware review time no later than assessment.

Even a matching envelope returns `unknown` pending independent reviewer authentication and assessment of date basis, identity and population/sector scope. `semantic_ready` and `publication_ready` are always false in this source-only tool. No edition, attribution, approval, privilege or public-release write is performed. Implementing an authenticated approval consumer requires a separately reviewed owner decision; this report cannot be used as that decision.

CI: run `python tests/cosenza_qa_db_check.py` immediately after `python tests/capture_rich_db_check.py` in the existing ephemeral PostgreSQL job. It verifies real SQL/readback, read-only transaction state, rejected count mismatch and blocked edition/semantic gates. The source workflow owner can add the CLI as a read-only follow-up step using exactly the persisted run returned by source persistence; default preflight stays read-only.
